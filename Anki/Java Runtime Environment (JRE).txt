## 🔹 Java Runtime Environment (JRE)

Это **среда выполнения Java-программ**.

👉 Если **JDK** нужно разработчику (чтобы писать и компилировать код), то **JRE** нужно пользователю (чтобы просто запускать готовые Java-приложения).

---

### В состав JRE входят:

* **JVM** (Java Virtual Machine) — исполняет байт-код.
* **Библиотеки классов Java** (Java Class Libraries) — готовые классы: работа со строками, файлами, сетью, GUI и т.д.
* **Инструменты для запуска приложений** (`java`, `javaw` и т.п.).

---

### Чего в JRE нет:

* Компилятора (`javac`).
* Инструментов разработчика (например, отладчика).

---

### Пример:

* Ты разработчик → ставишь **JDK** (оно включает в себя и JRE).
* Ты просто пользователь → тебе хватает **JRE**, чтобы запустить чужую программу на Java.

---

📌 Итог:

* **JVM** = виртуальная машина, исполняет байт-код.
* **JRE** = JVM + стандартные библиотеки → среда для запуска программ.
* **JDK** = JRE + инструменты разработки (компилятор, отладчик, профайлер).

- **JVM (Java Virtual Machine)** — виртуальная машина, которая интерпретирует байт-код

### 🧠 Как это работает

1. Ты пишешь код на Java → `MyProgram.java`
2. Компилируешь его → `javac` → получается `MyProgram.class` (байт-код)
3. JRE запускает этот `.class` файл через JVM → программа работает

| Компонент | Назначение                          |
|-----------|--------------------------------------|
| **JRE**   | Только для запуска Java-программ     |
| **JDK**   | Включает JRE + компилятор + инструменты разработки |

**Java Runtime Environment (JRE) - это**

JRE - это минимальная реализация виртуальной машины для **запуска** уже скомпилированных Java-приложений. Если говорить проще, JRE - это "проигрыватель" для программ, написанных на Java.

---

**Из чего состоит JRE?**

1.  **JVM (Java Virtual Machine)**
    - Исполняет байт-код (файлы .class)
    - Управляет памятью, выполняет JIT-компиляцию, сборку мусора

2.  **Стандартные библиотеки Java (Java Class Library)**
    - Готовые модули и классы для работы с коллекциями, вводом-выводом, сетью, многопоточностью и т.д.
    - Например: java.lang, java.util, java.io

3.  **Вспомогательные компоненты**
    - Плагины для запуска апплетов (устарело)
    - Утилиты для настройки и мониторинга (например, java - лаунчер для запуска приложений)

---

**Кому нужен JRE?**

- **Пользователям**, которые хотят запускать Java-приложения (например, Minecraft, Apache Tomcat, desktop приложения)
- **Не нужен разработчикам** - им требуется **JDK** (включает в себя JRE + компилятор и инструменты разработки)

---

**Эволюция JRE**

- До Java 8: JRE был отдельным пакетом для установки
- После Java 9: Введена модульная система. JRE как отдельный продукт упразднен
- **С Java 11+** Oracle не предоставляет отдельный JRE. Разработчики используют JDK, а для развертывания приложений создают минимальные образы через jlink

---

**Пример**

Чтобы запустить программу из скомпилированного .jar-файла, нужна команда:
```
java -jar myapp.jar
```
Здесь java - это инструмент из JRE, который запускает JVM и выполняет код.

---

**Важно!**

- JRE **не включает компилятор** (javac) - только среду для выполнения
- Для разработки всегда требуется **JDK** (Java Development Kit)

---

**Итог**

### JRE и JVM

* **JVM** — это сердце JRE. Она берёт скомпилированный байт-код Java (`.class` файлы) и выполняет его на конкретной платформе.
* **JRE** — это "упакованный" продукт, который включает JVM и всё необходимое для запуска программ. Она не содержит компилятора и других инструментов для разработки, поэтому для создания программ JRE недостаточно.

Проще говоря: **для запуска Java-программы нужен JRE, а для её написания — JDK.**

Она включает в себя всё, что нужно для выполнения Java-приложений, но не содержит инструментов для их разработки. Давай разберем, что такое JRE, его роль и как оно связано с изучением Java как первого языка программирования.

### Что такое JRE?
JRE (Java Runtime Environment) — это часть платформы Java, которая предоставляет:
1. **Java Virtual Machine (JVM)**: Основной компонент, который исполняет байт-код (скомпилированный код Java) на конкретной аппаратной платформе.
2. **Библиотеки Java (Java Class Library)**: Набор стандартных классов и функций (например, `java.util`, `java.io`), которые используются в программах.
3. **Дополнительные компоненты**: Утилиты и файлы, необходимые для работы JVM, такие как загрузчик классов и менеджер памяти.

JRE — это минимальный набор, чтобы **запускать** Java-программы, но он не включает компилятор (`javac`) или инструменты для написания кода, которые есть в Java Development Kit (JDK).

### Разница между JRE, JVM и JDK
- **JVM**: Виртуальная машина, которая выполняет байт-код. Это ядро JRE.
- **JRE**: JVM + стандартные библиотеки. Нужна, чтобы запускать готовые Java-программы.
- **JDK**: JRE + инструменты разработки (компилятор `javac`, дебаггер, утилиты). Нужен для написания и компиляции программ.

Если ты учишься программировать на Java, тебе нужен **JDK**, так как он включает JRE и инструменты для создания кода. JRE нужен, если ты только запускаешь готовые Java-приложения (например, Minecraft или корпоративное ПО).

### Роль JRE для новичков
1. **Запуск программ**: Когда ты компилируешь код (с помощью `javac`, входящего в JDK), JRE (через JVM) запускает его. Например, команда `java MyProgram` использует JRE.
2. **Кроссплатформенность**: JRE обеспечивает выполнение Java-программ на любой системе (Windows, macOS, Linux), где оно установлено.
3. **Простота для пользователей**: Если ты пишешь программу для других, им достаточно установить JRE, чтобы её запустить, без необходимости разбираться в программировании.

### Плюсы JRE для начинающих
- **Упрощает запуск**: Ты можешь сосредоточиться на написании кода, не беспокоясь о том, как он работает на уровне оборудования.
- **Автоматическое управление**: JRE через JVM управляет памятью (сборка мусора) и безопасностью, что снижает количество ошибок.
- **Широкая поддержка**: JRE доступна для большинства платформ, так что твои программы будут работать везде.

### Подводные камни JRE для новичков
1. **Установка и настройка**: Если JRE не установлена или настроена неправильно, ты можешь столкнуться с ошибками вроде `java: command not found`. Это может быть проблемой при настройке окружения.
2. **Ограничения JRE**: JRE не позволяет компилировать код. Если ты скачал только JRE вместо JDK, ты не сможешь писать и компилировать свои программы.
3. **Ошибки JVM**: Ошибки, связанные с JRE (например, `OutOfMemoryError`), могут быть непонятны новичкам, так как требуют понимания работы JVM.

### Практика для новичков
- **Проверь наличие JRE**: После установки JDK выполни в терминале команду `java -version`. Ты увидишь версию JRE, которая входит в JDK. Например:
  ```
  java version "17.0.8" 2023-07-18
  Java(TM) SE Runtime Environment (build 17.0.8+9-LTS-211)
  ```
- **Запусти программу**: Напиши простую программу, скомпилируй её (`javac MyProgram.java`) и запусти через JRE (`java MyProgram`):
  ```java
  public class MyProgram {
      public static void main(String[] args) {
          System.out.println("JRE запускает мой код!");
      }
  }
  ```
- **Совет**: Используй IDE (например, IntelliJ IDEA), которая автоматически настраивает JRE и JDK, чтобы избежать ручной настройки.

### Что нужно знать о JRE на старте?
- JRE — это то, что запускает твои Java-программы.
- Для обучения программированию скачивай JDK, так как он включает JRE и инструменты разработки.
- Понимание JRE на начальном этапе не обязательно, но знай, что она отвечает за выполнение твоего кода на любом устройстве.
