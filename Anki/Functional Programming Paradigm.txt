Functional Programming Paradigm

**Функциональный стиль программирования** — это способ писать код, где ты описываешь **что должно быть сделано**, а не **как именно это сделать шаг за шагом**.

---

## 🧠 Суть функционального стиля

- 📌 **Функции — как математические выражения**: они принимают вход, возвращают выход и не изменяют внешнее состояние
- 🔁 **Без побочных эффектов**: не меняют переменные, не пишут в файл, не мутируют объекты
- 🧱 **Иммутабельность**: данные не изменяются, а создаются новые версии
- 🧩 **Композиция**: функции можно комбинировать, передавать как аргументы, возвращать из других функций

---

## 🔧 Пример: императивный vs функциональный стиль

### Императивный (Java):
```java
List<Integer> result = new ArrayList<>();
for (int i : numbers) {
    if (i % 2 == 0) {
        result.add(i * i);
    }
}
```

### Функциональный (Java 8+):
```java
List<Integer> result = numbers.stream()
    .filter(i -> i % 2 == 0)
    .map(i -> i * i)
    .collect(Collectors.toList());
```

→ Вместо пошаговых инструкций — **декларативное описание**: фильтруем, преобразуем, собираем

---

## 🧬 Где это встречается

- **Java**: с появлением `Stream API`, `Optional`, `lambda` выражений  
- **Kotlin**: `map`, `filter`, `fold`, `let`, `run` — всё про композицию  
- **Python**: `map()`, `filter()`, `lambda`, `list comprehensions`  
- **JavaScript**: `Array.map()`, `reduce()`, `filter()`  
- **Haskell, Elixir, F#** — чисто функциональные языки
