try-catch

Конструкция try-catch — это фундаментальный механизм обработки исключений в Java. Вот подробное объяснение:

🧱 Что такое try-catch
Это способ сказать программе:
"Попробуй выполнить этот код.
 Если что-то пойдёт не так — не падай, а обработай ошибку аккуратно."

🔧 Как работает
try {
    // Код, который может вызвать ошибку
} catch (ExceptionType e) {
    // Код, который выполняется, если произошла ошибка
}

try — блок, где ты размещаешь потенциально опасный код (например, парсинг строки в число, работа с файлами, сетью и т.д.).
catch — блок, который перехватывает конкретный тип ошибки (например, NumberFormatException, IOException, NullPointerException) и позволяет тебе отреагировать: вывести сообщение, повторить попытку, записать лог, и т.д.

🧠 Зачем это нужно
Без try-catch, если возникает ошибка — программа аварийно завершится. Это плохо:
Пользователь теряет данные.
Программа выглядит ненадёжной.
Невозможно отладить или логировать проблему.
С try-catch ты получаешь:
Контроль над ошибками
Гибкость в реакции
Повышенную устойчивость — особенно важно в пользовательских интерфейсах, сетевых приложениях, и при работе с вводом.

🔍 Пример из твоего кода
try {
    return Double.parseDouble(input);
} catch (NumberFormatException e) {
    System.out.println("Ошибка: " + e.getMessage());
    e.printStackTrace(); // Выводит стек вызовов
    System.out.println("Invalid input");
    System.out.print("Please enter a valid decimal number: ");
}

Здесь ты защищаешь программу от ввода вроде "abc" или "3.14abc". Вместо падения — ты вежливо просишь пользователя ввести корректное число.

🧩 Архитектурная аналогия
Представь, что ты строишь модуль, который принимает данные от пользователя. Без try-catch — это как открытая дверь без замка: любой неверный ввод ломает систему. С try-catch — ты ставишь фильтр, который проверяет, что входит, и обрабатывает ошибки локально, не разрушая всю архитектуру.
